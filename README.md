Implementation has started. The current code contains Laravel domain modules and a legacy Next.js transition interface. The target release is a Laravel Blade, Livewire, Alpine.js, and Tailwind application that works on shared PHP hosting. Read `AGENTS.md` before implementation work. ## Shared-hosting direction

The baseline release must work with PHP, MySQL/MariaDB, host cron, writable Laravel storage, and a database queue/cache. Redis, Docker, persistent workers, Node.js, realtime broadcasting, and self-hosted media are optional enhancements. See [01 — Architecture](docs/01-architecture.md) and [08 — Operations](docs/08-operations.md). The current `.env.example` uses the shared-host database defaults; Docker Compose provides its own PostgreSQL and Redis values for local development.

## Run the first slice locally

1. Copy `.env.example` to `.env` at the repository root. Replace `DB_PASSWORD` with a unique value and set `APP_KEY` to a key generated by `php artisan key:generate --show` inside `services/api`.
2. Run `docker compose up -d --build` from the repository root.
3. Run `docker compose exec api php artisan migrate --force`.
4. Run `docker compose exec api php artisan ministry:install` in an interactive terminal. Enter the ministry and initial administrator details at the prompts. The administrator password is entered without echo and is not passed as a command argument.
5. Open `http://localhost:8080`. Staff sign-in is at `/admin/login` using the administrator email and password chosen during setup. The public API is at `/api/v1/public/site`; health is at `/up`.

The administrator can create a site-editor invitation in `/admin`. The one-time link is displayed once for private delivery; the default local mail transport does not send it. Invitation holders set their password at that link, then sign in. Staff can inspect, revoke, or sign out of all their sessions in `/admin`.

## Fast local development

For PHP, Blade, route, CSS, and JavaScript changes, use the source-mounted development profile instead of rebuilding the API image:

```text
docker compose -f compose.yaml -f compose.dev.yaml up -d --force-recreate api proxy vite
```

The Vite watcher serves assets on port 5173. Clear Laravel's caches if a route, view, or configuration change appears stale:

```text
docker compose -f compose.yaml -f compose.dev.yaml exec api php artisan optimize:clear
```

Build the API image only after changing Docker, Composer dependencies, PHP extensions, or when validating the production asset bundle.

## Operator checks and database backup

Run `docker compose exec api php artisan ministry:doctor --profile=local` to inspect the local installation. Use `php artisan ministry:doctor --profile=shared --strict` after configuring a shared host; it accepts database queue/cache fallbacks and verifies the host-cron scheduler heartbeat. The existing `production` profile remains for the enhanced deployment profile and does not replace live provider, TLS, queue, or media validation.

For an encrypted local database backup, create `secrets/backup_passphrase` with a strong, unique passphrase and keep a separate recovery copy. Then run:

```text
docker compose --profile ops build backup
docker compose --profile ops run --rm backup backup
docker compose --profile ops run --rm backup restore-verify <filename.pgdump.gpg>
```

Archives and checksums are written under the Git-ignored `backups/` directory. Restore verification creates an isolated `ministry_restore_*` database; it does not replace the active database. The current tool covers PostgreSQL only. Media objects must be added to the backup plan when object storage is configured. See [08 — Operations](docs/08-operations.md).

## Docker storage maintenance

To prevent Docker build cache from using unchecked disk space, run the included maintenance script from the repository root:

```powershell
./infra/maintenance/Invoke-DockerMaintenance.ps1
```

It caps BuildKit cache at 2 GB and removes dangling images. It does not remove running containers, named volumes, database data, or backups. The weekly Windows Task Scheduler setup is documented in [08 — Operations](docs/08-operations.md#62-docker-storage-maintenance).

This Compose file is for local evaluation on port 8080. A public deployment needs a real domain, TLS, backups, provider configuration, and the checks in [08 — Operations](docs/08-operations.md). Do not expose this local configuration directly to the internet.

For API tests, create a separate `ministry_test` database in the local PostgreSQL container, then run `docker compose -f compose.yaml -f compose.test.yaml run --rm api php artisan test`. The test override mounts the development checkout so PHPUnit is available; it must not be used for production.

For the shared-host MariaDB compatibility suite, run `docker compose -f compose.mysql.test.yaml run --rm api vendor/bin/phpunit --configuration phpunit.mysql.xml`. This profile is only for migration and contract validation; remove its temporary containers with `docker compose -f compose.mysql.test.yaml down` after the run.
